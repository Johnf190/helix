# workspace/categories — facts declare their category (ORDER 65, upgrade item 28, phase A)

A fact may say what it is about in its first 15 lines:

    Category: project: boats
    Category: project: boats · rules        (at most two, ` · ` or `,`; the first is primary)

| file | what |
|---|---|
| `CATEGORIES.txt` | the list: `name \| lobe \| colour \| description`. The **only** place a category name is written. `lobe` is one of mindgraph's seven (`helix research finance music mapapp making life`). Odin may append lines without an order. |
| `categories.py` | `load()`, `declared(text)`, `declared_all(text)`, `primary(path_or_text)`. Malformed list lines are skipped and listed in `load_errors`. Phase B (order 73b) adds `load_assigned`, `category_of`, `census` and the `assign` verb, the only writer of `ASSIGNED.csv`. |
| `propose_backfill.py` | reads `memory/facts/*.md` read-only, writes `BACKFILL_PROPOSAL.csv` / `.md` here. Rule-based (filename words, title words, cited facts' categories). Refuses any output path under `memory/`. Never opens a credentials file. |
| `test_categories.py` | `python3 -m pytest -q test_categories.py` |

## Who reads a declared category

- `mindgraph.py` (the v7 orb): the category's lobe, `cat_source: "declared"`; otherwise the filename guess.
  The graph cache is keyed on the list file's mtime too.
- app.py `/memory`: declared facts grouped under their category (list order, list colour); the rest
  as before (`MEMORY_CATS`, then MISC). Each node has `cat_source`.
- app.py `/blueprint`: declared category (uppercased) beats the `<!-- blueprint: project=… -->` tag
  and the filename keywords; each node has `cat_source` (`declared` / `tag` / `filename-guess`).

All three load `categories.py` from its path inside a `try`: if the module or the list breaks they
fall back to exactly the filename guesses (and the two routes to exactly their pre-ORDER-65 output).

## Phase B — ORDER 73b: the sidecar `ASSIGNED.csv`

Facts are append-only and builders never write them, so the old facts get their category from a
sidecar, not from a new line in the fact.

| file | what |
|---|---|
| `BACKFILL_PROPOSAL.csv` / `.md` | regenerated by `propose_backfill.py` (232 facts on 2026-10-23: 210 high, 22 low). |
| `OVERRIDES.csv` | `file,primary,secondary,why`. Written by Odin after the user approves (from `OVERRIDES_DRAFT.csv`). Absent is fine. |
| `ASSIGNED.csv` | `file,primary,secondary,source`. Written **only** by `categories.py assign`, never by hand. |

    python3 categories.py assign --dry      counts + "needs the user:" / "unknown:" lists; writes nothing
    python3 categories.py assign            rewrites ASSIGNED.csv (temp file + mv)

For every fact **without** a valid declared line (checked with `declared_all` on the fact itself):
an `OVERRIDES.csv` row wins (source `override`); else a high-confidence proposal row (source
`proposal`); else it is not assigned and listed `needs the user: <file>`. A row naming something not in
`CATEGORIES.txt` is not assigned and listed `unknown: <name> (<file>)`. A credentials file is never opened.

`category_of(name, text, cats, assigned)` → `(names, "declared")` for a valid declared line, else
`(names, "assigned")` from `ASSIGNED.csv`, else `([], None)`. A declared line naming something not on
the list falls through to `ASSIGNED.csv`. `/memory`, `/blueprint` and mindgraph read it, so a node's
`cat_source` is `declared`, `assigned` or (no category) the old guess. mindgraph's cache key includes
`ASSIGNED.csv`'s mtime, so a new `assign` shows on the next request.

The nightly line (after `- retired:`): `- categories: D declared · A assigned · U none`, 🟡 with the
first 3 files when U > 0, plus ` · 🟡 B bad declared lines (…)` when a declared line names something
not on the list. Built on `census()`.
